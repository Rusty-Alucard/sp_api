# Cursor ルール

このフォルダには、Cursor IDE向けの実装ルールが含まれています。これらのルールは`.mdc`ファイル形式で記述され、`applyAlways: true`設定により、すべての開発作業で自動的に適用されます。

## ルールファイル一覧

### [implementation-rules.mdc](./implementation-rules.mdc)
SP APIプロジェクトの基本実装ルールです。以下の内容を含みます：

- **基本原則**: テストファースト開発、ドキュメントファースト、コード品質
- **実装ルール**: ファイル構造、テストコード要件、ドキュメント要件
- **コード品質要件**: 静的解析、パフォーマンス、セキュリティ
- **実装チェックリスト**: 新規実装時と既存実装更新時のチェック項目
- **ツールと設定**: 使用するツールとその設定方法
- **品質ゲート**: プルリクエスト前とマージ前の品質確認項目

### [testing-guidelines.mdc](./testing-guidelines.mdc)
テストコードの実装ガイドラインです。以下の内容を含みます：

- **テスト戦略**: テストピラミッドとテストの種類
- **テスト実装パターン**: 単体テスト、統合テスト、E2Eテストの実装方法
- **テストデータ管理**: テストフィクスチャとテストデータファクトリ
- **ベストプラクティス**: テストの命名、アサーション、独立性、パフォーマンス

### [documentation-guidelines.mdc](./documentation-guidelines.mdc)
ドキュメント作成のガイドラインです。以下の内容を含みます：

- **ドキュメント構造**: ディレクトリ構成とドキュメントの種類
- **ドキュメント作成ルール**: 基本原則、記述スタイル、コードサンプル
- **図表の作成**: Mermaid図表の使用方法
- **ドキュメントテンプレート**: APIドキュメントと実装ガイドのテンプレート
- **品質基準**: 内容、形式、保守性の品質基準

### [implementation-checklist.mdc](./implementation-checklist.mdc)
実装の品質を確保するためのチェックリストです。以下の内容を含みます：

- **新規実装時のチェックリスト**: 設計、実装、テスト、ドキュメント、品質、パフォーマンス
- **既存実装更新時のチェックリスト**: 影響範囲分析、テスト更新、ドキュメント更新
- **ファイル別チェックリスト**: ドメイン層、アプリケーション層、インフラストラクチャ層
- **品質ゲート**: プルリクエスト前とマージ前の品質確認
- **自動化チェック**: CI/CDパイプラインとプリコミットフック

## 使用方法

### 自動適用
これらのルールは`applyAlways: true`設定により、Cursor IDEで自動的に適用されます。開発作業中に常にこれらのルールが参照され、実装の一貫性と品質が保たれます。

### 手動参照
必要に応じて、以下の方法でルールを手動で参照できます：

1. **Cursor IDE内**: `.mdc`ファイルを直接開いて内容を確認
2. **コマンドライン**: `cat docs/rules/cursor/*.mdc`で全ルールを表示
3. **GitHub**: リポジトリ内でルールファイルを閲覧

### ルールの更新
ルールを更新する場合は、以下の手順に従ってください：

1. 該当する`.mdc`ファイルを編集
2. 変更内容をコミット
3. チーム内で変更内容を共有
4. 必要に応じてドキュメントを更新

## ルールの適用範囲

### 適用される作業
- 新規機能の実装
- 既存機能の修正・拡張
- バグ修正
- リファクタリング
- テストコードの作成・更新
- ドキュメントの作成・更新

### 適用されない作業
- 緊急対応（ただし、事後の追加実装は必要）
- 実験的実装（ただし、本番マージ前の品質ゲートは必要）

## 品質管理

### ルールの遵守確認
- **自動チェック**: CI/CDパイプラインでの自動チェック
- **コードレビュー**: プルリクエストでの手動チェック
- **定期的監査**: 月次でのルール遵守状況の確認

### ルールの改善
- **フィードバック収集**: 開発チームからのフィードバック
- **ベストプラクティス共有**: チーム内での経験共有
- **ツール更新**: 新しいツールや手法の導入検討

## トラブルシューティング

### よくある問題

**問題**: ルールが適用されない  
**原因**: `.mdc`ファイルの`applyAlways: true`設定が正しくない  
**解決法**: ファイルの先頭に正しいYAMLフロントマターを設定

**問題**: ルールが古い  
**原因**: ルールファイルが更新されていない  
**解決法**: 最新のルールファイルを確認し、必要に応じて更新

**問題**: ルールが厳しすぎる  
**原因**: プロジェクトの状況に合わないルール設定  
**解決法**: チーム内で議論し、適切なルールに調整
